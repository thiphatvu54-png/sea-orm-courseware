Lesson 0003 · 约 20 分钟

用 Entity 插入一行，再用查询把它读回来

上一课已经导入 users 表。本课把 SQL 表结构连接到 SeaORM 的 ActiveModel 和查询 API，完成一次可验证的 CRUD 闭环。

1. 定义最小 Entity

use sea_orm::entity::prelude::*;

#[derive(Clone, Debug, DeriveEntityModel)]
#[sea_orm(table_name = "users")]
pub struct Model {
    #[sea_orm(primary_key)]
    pub id: i32,
    pub email: String,
    pub display_name: String,
    pub created_at: String,
}

#[derive(Copy, Clone, Debug, EnumIter, DeriveRelation)]
pub enum Relation {}

impl ActiveModelBehavior for ActiveModel {}

Model 表示查询结果的一行；ActiveModel 表示要插入或更新的值；Entity 提供查询入口。

2. 插入一行

use sea_orm::{ActiveModelTrait, Set};

let user = user::ActiveModel {
    email: Set("alice@example.com".to_owned()),
    display_name: Set("Alice".to_owned()),
    ..Default::default()
};
let inserted = user.insert(&db).await?;
assert_eq!(inserted.email, "alice@example.com");

没有手动赋值的自增主键和默认时间交给数据库生成。insert 返回完整的 Model，可以马上断言。

3. 查询并验证

use sea_orm::{ColumnTrait, EntityTrait, QueryFilter};

let found = user::Entity::find()
    .filter(user::Column::Email.eq("alice@example.com"))
    .one(&db)
    .await?;

assert_eq!(found.map(|m| m.display_name), Some("Alice".to_owned()));

filter 组合条件，one 最多取一行并返回 Option<Model>。找不到数据时得到 None，而不是异常。

关键心智模型：Entity 是查询入口，ActiveModel 是写入草稿，Model 是数据库返回的只读结果。数据库约束仍然是最后一道防线。

4. 回忆练习

  2. 把邮箱改成已存在的值时，哪一层会阻止写入？
  3. 把 one(&db) 改成查询全部用户，应该使用哪个方法？
