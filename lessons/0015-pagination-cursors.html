为列表接口选择分页方式

分页查询必须有稳定排序。偏移分页适合跳到任意页，游标分页适合无限滚动和深页读取。

1. 偏移分页：LIMIT + OFFSET

let mut pages = post::Entity::find()
    .order_by_asc(post::Column::Id)
    .paginate(db, 20);

let rows = pages.fetch_page(2).await?;

第 2 页、每页 20 条的概念 SQL：

SELECT "post".*
FROM "post"
ORDER BY "id" ASC
LIMIT 20 OFFSET 40;

优点是可以直接跳页；缺点是深页需要跳过大量行，数据变化时也更容易出现重复或遗漏。

2. 游标分页：从上一页最后一个键继续

let mut cursor = post::Entity::find()
    .order_by_asc(post::Column::Id)
    .cursor_by(post::Column::Id);

cursor.after(last_id);
let rows = cursor.first(20).all(db).await?;

概念 SQL：

SELECT "post".*
FROM "post"
WHERE "id" > $1
ORDER BY "id" ASC
LIMIT 20;

游标列必须有稳定排序；实际项目中通常选择唯一且有索引的键，或使用 (created_at, id) 这样的复合游标。

练习：后台管理页面需要跳到第 50 页，移动端信息流只需要“加载更多”。分别选择哪种分页方式？为什么？
