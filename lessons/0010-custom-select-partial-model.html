只查询需要的列：select_only 与 PartialModel

关联查询返回完整 Model 很方便，但列表接口常常只需要少数列。本课学习如何减少 SQL 返回的数据，并把查询结果映射成 DTO。

1. 传统方式：select_only

建议文件：src/services/category_service.rs 或现有查询 service 文件

use sea_orm::{ColumnTrait, EntityTrait, QuerySelect};

let rows = category::Entity::find()
    .select_only()
    .column(category::Column::Id)
    .column(category::Column::Name)
    .filter(category::Column::Name.contains("book"))
    .all(db)
    .await?;

select_only() 清空默认列，再用 column 指定需要的列。这样不会把详情字段全部读出来。

2. 用 column_as 给表达式命名

use sea_orm::{Expr, QuerySelect};

let rows = order::Entity::find()
    .select_only()
    .column(order::Column::Id)
    .column_as(order::Column::Total.sum(), "total_amount")
    .into_tuple::<(i64, Decimal)>()
    .all(db)
    .await?;

聚合表达式必须有别名，别名要和结果结构或 tuple 的顺序对应。

3. SeaORM 2.0 推荐：DerivePartialModel

文件：src/dtos/categories.rs 或查询专用 DTO 文件

use sea_orm::DerivePartialModel;

#[derive(Debug, sea_orm::DerivePartialModel)]
#[sea_orm(entity = "category::Entity")]
pub struct CategoryListItem {
    pub id: i32,
    pub name: String,
}

let rows: Vec<CategoryListItem> = category::Entity::find()
    .into_partial_model()
    .filter(category::Column::Name.contains("book"))
    .all(db)
    .await?;

PartialModel 让结构体字段成为“查询列清单”，比手动维护 select_only 更不容易漏改。

4. 在 controller 返回 Response

文件：src/controllers/categories.rs

pub async fn list(
    State(ctx): State<AppContext>,
) -> loco_rs::Result<Response> {
    let rows = category_service::list_summary(&ctx.db).await?;
    loco_rs::controller::format::json(rows)
}

查询放 service，HTTP Response 放 controller：这样数据库查询和接口格式不会混在一起。

5. 验证 SQL 与效果

cargo test
cargo loco routes

打开 SeaORM debug log，确认列表接口只 SELECT 需要的列；大表分页时继续结合第 6 课的分页方法。

回忆题：select_only 的作用是什么？什么时候更适合用 DerivePartialModel？
答案

它清空默认选择列；当接口有稳定的列表 DTO、且不想手写列清单时，使用 PartialModel 更清晰。
