Lesson 0011 · SeaORM · 约 15 分钟

把查询列清单变成可回归的测试

第 10 课解决了“查询哪些列”。本课解决“以后怎么保证它仍然只查询这些列”。

1. 直接检查生成的 SQL

use sea_orm::{DbBackend, DerivePartialModel, QueryTrait};

#[derive(Debug, DerivePartialModel)]
#[sea_orm(entity = "user::Entity")]
struct UserListItem {
    pub id: i32,
    pub email: String,
}

let sql = user::Entity::find()
    .into_partial_model::<UserListItem>()
    .build(DbBackend::Postgres)
    .to_string();

assert!(sql.contains("\"id\""));
assert!(sql.contains("\"email\""));
assert!(!sql.contains("\"password_hash\""));

build(...).to_string() 适合验证 SQL 形状：列是否存在、敏感列是否意外出现、别名是否正确。

2. 用 MockDatabase 验证查询流程

// Cargo.toml：启用 sea-orm 的 mock feature
let db = MockDatabase::new(DatabaseBackend::Postgres)
    .append_query_results([vec![UserListItem { id: 1, email: "a@x.test".into() }]])
    .into_connection();

let rows = user::Entity::find()
    .into_partial_model::<UserListItem>()
    .all(&db)
    .await?;

assert_eq!(rows[0].email, "a@x.test");

MockDatabase 不连接真实数据库；它提供预设结果，并记录执行过的查询，适合快速验证映射和应用逻辑。

练习：为什么“检查生成 SQL”与“MockDatabase 返回结果”是两种互补的测试？各自能发现什么错误？
