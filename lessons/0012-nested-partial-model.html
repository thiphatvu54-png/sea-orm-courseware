用嵌套 DTO 表达关联查询

当列表同时需要主表和关联表的少数列时，#[sea_orm(nested)] 可以让 DTO 结构直接表达查询结果。

1. 定义父 DTO 与子 DTO

use sea_orm::DerivePartialModel;

#[derive(Debug, DerivePartialModel)]
#[sea_orm(entity = "cake::Entity")]
struct CakeList {
    pub id: i32,
    pub name: String,
    #[sea_orm(nested)]
    pub bakery: Option<BakeryList>,
}

#[derive(Debug, DerivePartialModel)]
#[sea_orm(entity = "bakery::Entity")]
struct BakeryList {
    pub id: i32,
    #[sea_orm(from_col = "name")]
    pub brand: String,
}

Option<BakeryList> 对应左连接：没有关联面包店时，结果可以是 None。from_col 把实体列 name 映射到 DTO 字段 brand。

2. 让查询由 DTO 驱动

let rows: Vec<CakeList> = cake::Entity::find()
    .left_join(bakery::Entity)
    .into_partial_model()
    .all(db)
    .await?;

SeaORM 会根据嵌套结构选择所需列，并为关联列生成前缀别名，避免两个表都有 id、name 时发生冲突。

练习：解释为什么这里用 Option<BakeryList>，以及 from_col = "name" 解决了什么问题。
