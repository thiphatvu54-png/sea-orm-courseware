用唯一键处理重复请求

幂等写入的关键不是在 Rust 里先查再插入，而是让数据库唯一约束定义冲突边界。

1. 重复时更新：DO UPDATE

use sea_orm::{ActiveValue::Set, EntityTrait};
use sea_orm::sea_query::OnConflict;

user::Entity::insert(user::ActiveModel {
    email: Set("a@x.test".into()),
    name: Set("Alice".into()),
    ..Default::default()
})
.on_conflict(
    OnConflict::column(user::Column::Email)
        .update_column(user::Column::Name)
        .to_owned()
)
.exec(db)
.await?;
CREATE UNIQUE INDEX users_email_key ON "user" ("email");

INSERT INTO "user" ("email", "name")
VALUES ('a@x.test', 'Alice')
ON CONFLICT ("email") DO UPDATE
SET "name" = EXCLUDED."name";

2. 重复时忽略：DO NOTHING

.on_conflict(
    OnConflict::column(user::Column::Email)
        .do_nothing()
        .to_owned()
)
INSERT INTO "user" ("email", "name")
VALUES ('a@x.test', 'Alice')
ON CONFLICT ("email") DO NOTHING;

注册接口通常只允许第一次创建，适合 DO NOTHING；资料同步接口希望覆盖最新字段，适合 DO UPDATE。

练习：“重复注册同一邮箱”和“同步用户最新昵称”分别选择 DO NOTHING 还是 DO UPDATE？
