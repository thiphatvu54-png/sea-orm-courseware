直接导入 SQL，再用 SeaORM 读写 users

本课只完成一个目标：把一段建表 SQL 执行到 SQLite 内存数据库，然后理解 Entity 和表结构如何对应。

1. 建表 SQL

CREATE TABLE IF NOT EXISTS users (
    id INTEGER RRIMARY KEY AUTOINCREMENT,
    email TEXT NOT NULL UNIQUE,
    display_name TEXT NOT NULL,
    created_at TEXT NOT NULL DEFAULT CURRENT_TIMESTAMP
);

完整文件在 sql/0002-create-user.sql。SQLite 的 INTEGER PRIMARY KEY 会承担自增主键职责。

2. 在 SeaORM 中执行 SQL

use sea_orm::{ConnectionTrait, Database, DbBackend, Statement};

let db = Database::connect("sqlite::memory:").await?;
db.execute(Statement::from_string(
    DbBackend::Sqlite,
    include_str!("../sql/0002-create-user.sql").to_owned(),
)).await?;

include_str! 在编译时把 SQL 文件读入程序；execute 通过连接执行它。真实项目通常会把这段逻辑放入 migration，而不是每次启动都建表。

3. Entity 与表的对应关系

  • user::Entity 对应 users 表。
  • user::Model 的字段对应一行数据：id、email、display_name、created_at。
  • user::Column::Email 对应 SQL 列 email。

4. 回忆练习

  1. 为什么 SQL 使用 UNIQUE 约束，而不是只在 Rust 中检查邮箱？
  2. 把 display_name 改成可空，SQL 和 Model 类型分别要怎么改？
  3. 解释 include_str! 与运行时读取文件的差别。
