把 CRUD 补完整：更新、删除与事务

上一课已经能插入并查询用户。本课学习如何把查询结果转换成 ActiveModel，安全地更新和删除，并用事务保证多步操作的一致性。

1. 更新一行

use sea_orm::{ActiveModelTrait, EntityTrait, Set};

if let Some(model) = user::Entity::find_by_id(1).one(&db).await? {
    let mut active: user::ActiveModel = model.into();
    active.display_name = Set("Alice Chen".to_owned());
    let updated = active.update(&db).await?;
    assert_eq!(updated.display_name, "Alice Chen");
}

查询得到的 Model 可以通过 into() 转成 ActiveModel。只修改需要变化的字段，再调用 update。

2. 删除一行

use sea_orm::EntityTrait;

user::Entity::delete_by_id(1).exec(&db).await?;
let missing = user::Entity::find_by_id(1).one(&db).await?;
assert!(missing.is_none());

删除前应先确认业务权限；数据库层的外键和级联规则也会影响删除是否成功。

3. 用事务包住多步写入

use sea_orm::{ConnectionTrait, TransactionTrait};

let txn = db.begin().await?;
// 在 txn 上执行多次 insert / update
// 任意一步返回 Err，整个事务都可以回滚
user::Entity::insert(active_user).exec(&txn).await?;
txn.commit().await?;

事务把多次写操作变成一个原子单元。真实业务中不要混用 &db 和 &txn，同一组操作应全部使用事务连接。

安全检查：更新和删除都要带明确条件；先用查询验证目标，再执行写操作。不要把用户输入直接拼进 SQL 字符串。

4. 回忆练习

  1. Model 为什么要转换成 ActiveModel 才能更新？
  2. 如果事务中的第二次写入失败，第一次写入应该是什么状态？
  3. 批量删除时，如何避免误删全部用户？

提交答案后再继续：写出“查询 → 修改字段 → update”的三步代码，并说明事务何时需要 rollback。
