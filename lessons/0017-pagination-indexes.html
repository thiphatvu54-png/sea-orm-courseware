让复合游标真正走索引

分页条件、排序条件和索引顺序应该互相匹配。否则虽然 SQL 正确，数据库仍可能扫描大量无关行。

1. Rust 查询

let mut cursor = post::Entity::find()
    .filter(post::Column::Status.eq("published"))
    .order_by_desc(post::Column::CreatedAt)
    .order_by_desc(post::Column::Id)
    .cursor_by((post::Column::CreatedAt, post::Column::Id));

cursor.after((last_created_at, last_id));
let rows = cursor.first(20).all(db).await?;

2. 对应 SQL 与索引

SELECT id, status, created_at, title
FROM "post"
WHERE status = 'published'
  AND (created_at, id) < ($1, $2)
ORDER BY created_at DESC, id DESC
LIMIT 20;

CREATE INDEX idx_post_status_created_id
ON "post" (status, created_at DESC, id DESC);

把过滤列 status 放在索引前缀，把游标和排序列放在后面，数据库更容易直接定位到下一页。

3. 用 EXPLAIN 验证

EXPLAIN (ANALYZE, BUFFERS)
SELECT id, status, created_at, title
FROM "post"
WHERE status = 'published'
  AND (created_at, id) < ($1, $2)
ORDER BY created_at DESC, id DESC
LIMIT 20;
Limit
  -> Index Scan using idx_post_status_created_id on post
       Index Cond: (
         status = 'published'
         AND (created_at, id) < ($1, $2)
       )

上面的计划是 PostgreSQL 风格的概念输出；真实计划要看数据量、统计信息和数据库版本。

练习：如果只有 (created_at, id) 索引，没有把 status 放进索引，为什么仍可能扫描大量非 published 行？
