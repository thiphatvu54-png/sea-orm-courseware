把多个写操作变成一个原子动作

Service 层定义事务边界；Controller 只调用 Service。任一步写入失败，整个事务回滚。

Rust 代码

let user_id = db
    .transaction::<_, _, DbErr>(|txn| {
        Box::pin(async move {
            let user = user::ActiveModel {
                name: Set("Alice".into()),
                ..Default::default()
            }
            .insert(txn)
            .await?;

            order::ActiveModel {
                user_id: Set(user.id),
                ..Default::default()
            }
            .insert(txn)
            .await?;

            Ok(user.id)
        })
    })
    .await?;

成功时的 SQL

BEGIN;
INSERT INTO "user" ("name") VALUES ('Alice');
INSERT INTO "order" ("user_id") VALUES (1);
COMMIT;

第二次写入失败时

BEGIN;
INSERT INTO "user" ("name") VALUES ('Alice');
ROLLBACK;

? 会把错误传播到事务边界；不会留下只创建用户、却没有订单的半成品。

练习：如果第二次 INSERT 失败，最终状态是 COMMIT 还是 ROLLBACK？数据库里是否会保留 Alice？
