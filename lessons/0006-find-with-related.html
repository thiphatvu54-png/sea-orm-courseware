读懂 find_with_related 的返回值

第 5 课已经建立用户和订单的关系。本课专门练习如何查询父记录及其子记录，并正确处理结果中的一对多结构。

1. 最小查询

let rows = user::Entity::find()
    .find_with_related(order::Entity)
    .all(&db)
    .await?;

rows 不是单个用户，也不是扁平的订单数组，而是一个二元组：每个元素包含一个 user::Model 和对应的 Vec<order::Model>。

2. 遍历用户和订单

for (user, orders) in rows {
    println!("{}: {} orders", user.email, orders.len());

    for order in orders {
        println!("order #{} amount={}", order.id, order.amount);
    }
}

没有订单的用户仍然会出现在结果中，只是对应的 orders 为空数组。这一点与 SQL 的 LEFT JOIN 语义相似。

3. 先过滤父记录

let rows = user::Entity::find()
    .filter(user::Column::Email.eq("alice@example.com"))
    .find_with_related(order::Entity)
    .all(&db)
    .await?;

过滤条件应尽量放在数据库查询中，而不是把所有用户和订单读到 Rust 内存后再筛选。

4. 只需要一个父记录时

let result = user::Entity::find_by_id(1)
    .find_with_related(order::Entity)
    .all(&db)
    .await?;

if let Some((user, orders)) = result.into_iter().next() {
    println!("{} has {} orders", user.email, orders.len());
}

关联查询仍然返回集合，因为数据库查询本质上可能产生多行。要得到单个父对象，可以在 Rust 侧取第一个元素并处理空结果。

性能提醒：关联查询适合一次加载明确的关系；关系层级很深或数据量很大时，应增加过滤、分页和列选择，避免一次读取过多数据。

5. 回忆练习

  1. find_with_related 返回的二元组两部分分别是什么？
  2. 一个用户没有订单时，orders 是什么值？
  3. 为什么应该尽量在数据库层 filter，而不是查询后再过滤？
